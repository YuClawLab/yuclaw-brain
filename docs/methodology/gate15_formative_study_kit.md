## 1. Version binding (hashes, not names)
Every session record binds the exact materials by SHA-256 + byte length and the source identity of the checkout they came from. The binding list is generated, never typed: `docs/methodology/gate15_materials_manifest.json` (written by `python3 tools/yuclaw_gate15_materials.py --write`, optionally `--wheel <file> --wheel-label REHEARSAL|RC|FINAL --packet <dir>`). It carries, per material, `path`, `sha256`, `size_bytes`, `source_head`, `source_tree` and, for the wheel, its label. Materials:

| material | role in the study |
|---|---|
| this document (protocol) | rules of the study |
| `docs/methodology/gate15_participant_script.md` | what the participant receives — contains no answers |
| `docs/methodology/gate15_reviewer_scoring_key.md` | what the reviewer scores against — never given to participants |
| `README.md` (contains the frozen CLI transcript used as Task 1 material) | Task 1 input |
| the offline verification packet built for the study (`PACKET_MANIFEST.json` digest recorded) | Task 2 input |
| `docs/evidence_scoreboard.html` and `docs/receipts/scoreboard.json` | Task 3 input |
| `docs/index.html` and `docs/capabilities.json` | Task 4 input |
| the wheel handed to the participant, if any — labeled REHEARSAL, RC or FINAL | Task 2 environment |

Rules: a session against any material whose hash differs from the manifest is a different study. The study asks about **the supplied artifact**; it never implies that a wheel not yet built was tested. If a later release ships materials whose hashes are identical to the manifest's, the result may be cited for that release only with an explicit identity comparison (`sha256` equality per material) and a claim scoped to those materials; a rebuilt wheel with a different hash is not covered.

## 2. Enrollment and denominator (fixed)
- **N = 5 enrolled**, fixed at enrollment; the primary fraction's denominator is always 5. A participant who withdraws, does not show, is ASSISTED, or times out stays in the denominator as a non-PASS — nobody is removed to improve the fraction.
- Eligibility: adults able to read English technical documentation; no YUCLAW authorship; not owner-affiliated (declared relationship RELATED-DISCLOSED or UNRELATED); no outcome-dependent incentive (a fixed, outcome-independent honorarium is permitted if the owner adopts one).
- Each participant receives: the participant script, the packet directory (with its `VERIFY.md`, which carries the recorded verify output and the challenge template), the README, and local copies of the site pages listed above at the bound hashes (the live site only if its served bytes equal the manifest at session start — recorded). Nothing else — never the scoring key.
- **Modes.** EXECUTION mode: the participant also has a computer with the `yuclaw` command installed from the bound wheel (label REHEARSAL/RC/FINAL recorded) and runs Tasks 2 and 5. TRANSCRIPT mode: no environment; Tasks 2 and 5 use the recorded verify output and the challenge template in `VERIFY.md`. The mode is fixed per session before it starts and written on the answer sheet. **The declared primary result is EXECUTION mode**; TRANSCRIPT sessions are reported as a separate secondary result and are never pooled with EXECUTION sessions. A session for which the bound wheel or environment is unavailable at session start becomes a TRANSCRIPT session (not MISSING) and is reported as such; if fewer than five EXECUTION sessions exist, the primary result is reported as `n_pass / 5` with the shortfall counted as MISSING, never filled from TRANSCRIPT sessions.

## 3. Task script, scoring key, participant packet and schema
The kit, scoring key and decision form share ONE machine-readable schema (`v3/study/gate15_schema.py`; `python3 tools/yuclaw_gate15_study.py schema`); `check-docs` verifies that both documents agree with it. The participant packet is built by `python3 tools/yuclaw_gate15_study.py build-packet <out> --source <checkout> --mode EXECUTION|TRANSCRIPT [--wheel <file> --wheel-label REHEARSAL|RC|FINAL]`: it contains the participant script, the README and site inputs, the verification packet with its `VERIFY.md` (recorded verify output and the complete challenge template) and, in EXECUTION mode, the declared wheel — never the scoring key. **Access/contamination policy:** the scoring key is published under `docs/methodology/` (it is not secret); participants are instructed not to open that folder during the session and to say so if they did; a session in which the participant reports having read the key is recorded ASSISTED. The private final study manifest (`manifest --commit <sha> --packet <dir>`) binds every material from the commit's blobs and the delivered bytes, so it never hashes a working copy and avoids a commit self-reference loop; the public `gate15_materials_manifest.json` is a WORKING COPY for development only.
The five tasks the participant sees are in `gate15_participant_script.md` (both modes; complete commands, no placeholders except the participant's own values; no answers). The expected elements and critical errors per task are in `gate15_reviewer_scoring_key.md`. Scoring rule: a task PASSES only when it was completed in 10 minutes, **every** expected element is present, and no critical error appears; a completed answer that merely avoids the listed wrong statements but lacks an expected element is FAIL (incomplete). The reviewer records every element tick and every critical-error tick in the decision form.

## 5. Session and study outcomes (precise)
- **Session PASS**: all five tasks completed with zero critical errors. **Session FAIL**: any critical error, or any INCOMPLETE task. **MISSING**: enrolled participant with no completed session (withdrawal, no-show). **ASSISTED**: any live help during a task — the session is recorded and reported, but counted as non-PASS in the primary fraction (a documented fallback such as reading `VERIFY.md` is not assistance).
- **Primary fraction** = PASS sessions / 5. **Candidate threshold (pending owner adoption): ≥ 4 of 5**, over **all five tasks** (this changes the earlier draft, which scored tasks 1–4 only; the change is explicit and unadopted).
- **Single proposed disclosure (aggregate only):** the public record is `n_pass / 5` for the EXECUTION mode (primary) and, separately, `n_pass / n_enrolled` for TRANSCRIPT sessions if any, plus the aggregate counts of FAIL, MISSING and ASSISTED sessions per mode, the materials manifest digest and the wheel label. No per-session labels, answers, timings or notes are published. Formative notes are summarized in prose, separately from the gate result, without session attribution.
- A study result becomes a gate input only after the owner adopts this protocol and the release-policy actor records the change; until then the gate stays MANUAL_REVIEW on current evidence.

## 6. Data, consent and disclosure (owner/ethics decision; nothing here is advice or a determination)
- **Session code**: a pseudonymous label for bookkeeping. It is not anonymity: the reviewer can link it to the enrolled person until the enrollment list is destroyed. No claim of a legal or ethics exemption is made here; applicability is the owner's/institution's determination (template in the private review material).
- **Option A (minimal data)**: no recording. Retained privately after scoring: the reviewer decision form only (session code, mode, per-task element/critical ticks, minutes, reviewer notes written as behaviour descriptions — no quotations of anything personal, no names, no contact data). Written answer sheets are destroyed after scoring.
- **Option B**: screen recording with explicit consent, deleted after scoring; everything else as in A.
- **Proposed retention (both options):** the enrollment list (session code ↔ person) is held by the owner only until the public aggregate is published, then destroyed; reviewer decision forms are retained privately for 12 months after publication, then destroyed; nothing per-session is ever published. Applicability of any review regime and the consent text remain owner decisions.
- Either option: consent text states the purpose (comprehension of a research tool, not evaluation of the person), withdrawal at any time (recorded as MISSING; the denominator stays 5), and that public output is the aggregate only. No names in any public artifact.

## 7. Reviewer decision form (per session; private)
`{session_code, mode, protocol_id, materials_manifest_sha256, wheel: {label, artifact_type, sha256, size_bytes}, tasks: [{task, completed, minutes, elements, critical, note}], assistance, relationship, reviewer_role, decided_at, synthetic}` — stored privately; only aggregate counts are published. The session decision (PASS/FAIL/MISSING/ASSISTED) is derived by the evaluator from the ticks, never entered by hand. The wheel is bound by its full sha256 and byte length (the label REHEARSAL/RC/FINAL is descriptive only); EXECUTION sessions need a bound wheel. Sessions form a cohort by (mode, protocol version, materials manifest, wheel bytes); cohorts are never pooled. Each session code must be distinct — a copied session is rejected, not counted. Minutes must be a finite number; `synthetic: true` forms are exercised by tests and can never become a gate input, whatever records accompany them. A gate input additionally needs trusted records: the adopted-protocol record bound to this materials manifest, the applicability determination, the study reviewer's DESIGNATED appointment resolved from the receipt store's appointment file, and one human session record per session signed by that reviewer.

Two distinct decision paths exist for the owner and are listed in the private V7-004-V3 review material: (1) an actual authorized study under this protocol; (2) an explicit, recorded release-policy exception that leaves the human comprehension result unpassed. Neither is selected here.
