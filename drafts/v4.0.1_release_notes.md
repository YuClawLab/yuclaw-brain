# YUCLAW v4.0.1 — Zero-Backend Demo (recommended install)

> **DRAFT — for VinZhang review before the GitHub release is published.**

**4.0.1 is the recommended install.** 4.0.0 was functional but the flagship demo required a local
Postgres backend a fresh user wouldn't have. 4.0.1 makes the marketed first experience actually work:

```bash
pip install yuclaw
yuclaw demo
```

On a brand-new machine with **no backend**, `yuclaw demo` now runs the full ~3-minute guided journey
offline against a bundled, frozen capture of the canonical **AMD @ 2026-05-20** signal — **including
the ledger-verification step**, which recomputes the **byte-identical** `content_hash`
(`fe7ca6df…c3195e6`) committed to the public git-anchored ledger. The evidence-first proof holds with
zero configuration.

## What's new
- **Bundled zero-backend demo** (`v4/demo/fixtures/` + `v4/demo/fixture_loader.py`). The demo and the
  demo-targeted commands resolve the canonical signal offline:
  - `yuclaw why AMD --as-of 2026-05-20` → Watch, Grade C, 8 source events
  - `yuclaw memo AMD --as-of 2026-05-20` → full research memo
  - `yuclaw share AMD --as-of 2026-05-20` → self-contained HTML card
  - `yuclaw verify AMD --date 2026-05-20` → recomputes `fe7ca6df…` → **VERIFIED**
  - `yuclaw cascade AMD --as-of 2026-05-20` → HPE → AMD supply cascade
- Any **other** ticker or date offline prints a clear backend-setup hint
  ([`docs/v4/backend_setup.md`](../docs/v4/backend_setup.md)), not an error.

## Upgrade
```bash
pip install --upgrade yuclaw     # 4.0.1
```
No API changes. The live-backend path is byte-for-byte unchanged from 4.0.0 (compliance regression
21/21; the fallback triggers only when Postgres is unreachable).

## Notes
- The bundled fixture is a frozen capture of one real signal (~14 KB). Live signals for any ticker/date
  still require a YUCLAW backend — see `docs/v4/backend_setup.md`.
- The `main` branch reconciliation remains tracked in `docs/v4.1/backlog.md` (see `MAIN_BRANCH_NOTICE.md`).
